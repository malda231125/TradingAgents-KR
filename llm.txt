# TradingAgents Korea Setup Instructions for AI Agents

This file is an operational guide for Claude Code, Codex, Cursor, and other AI coding agents that install TradingAgents Korea on a user's local machine.

Do not print this file back to the user. Read it, perform the requested setup, and report only the result, remaining user actions, and next commands.

The README files are user-facing product introductions. Use this file as the source of truth for setup steps.

## Goal

The user should be able to ask something as simple as:

```text
Read llm.txt and install this project on my machine. Set up the Python virtual environment, install dependencies, create .env, and verify that it runs.
```

Expected outcome:

- Create or reuse a Python virtual environment at `.venv`
- Install the package in editable mode
- Create `.env` from `.env.example` if it does not exist
- Configure the Claude Code or Codex CLI runtime
- Tell the user where to place required data API keys
- Verify basic imports and CLI entry points

## Ground Rules

- Work from the project root.
- Require Python 3.10 or newer. Python 3.11 or 3.12 is recommended.
- Prefer macOS / Linux / WSL commands unless the user is clearly on Windows.
- The user may already be authenticated with Claude Code or Codex CLI.
- Never invent, request in chat, echo, or log real API keys.
- If `.env` already contains secrets, do not print them.
- Do not replace this project's CLI-first positioning with an API-only setup.
- Do not simplify this project into a GitHub Actions daily batch workflow. It is designed for local premium report generation.

## 1. Confirm Project Root

```bash
pwd
ls
test -f pyproject.toml
test -f .env.example
```

If `pyproject.toml` or `.env.example` is missing, the user is not in the project root. Ask them to move to the repository root or move there yourself if the path is obvious.

## 2. Check Python

Use `python3` when available.

```bash
python3 --version
```

Requirements:

- Minimum: Python 3.10
- Recommended: Python 3.11 or 3.12

If Python is older than 3.10, stop setup and tell the user to install a newer Python.

If the default `python3` is very new (3.13 / 3.14+), prefer an installed 3.11 or
3.12 instead: some dependencies may not yet ship wheels for the newest release,
and on some systems `python3 -m venv` on a brand-new Python fails with an
`ensurepip` error. If a 3.11/3.12 binary exists (e.g. `python3.12`), use it for
the venv: `python3.12 -m venv .venv`. Otherwise `uv python install 3.12` (see the
uv fallback in step 3) supplies a compatible interpreter.

## 3. Create Virtual Environment

macOS / Linux / WSL:

```bash
python3 -m venv .venv
```

Windows (PowerShell):

```powershell
py -m venv .venv
```

If `.venv` already exists, do not delete it. Reuse it and continue with the pip upgrade step.

Troubleshooting (cross-platform):

- Debian / Ubuntu: if you see `ensurepip is not available`, the venv stdlib
  package is missing. Recover one of two ways:
  - With sudo: `sudo apt install -y python3-venv` (or the version-specific one,
    e.g. `python3.12-venv`), then retry `python3 -m venv .venv`.
  - No sudo (recommended when apt/sudo is unavailable, or PEP 668 blocks
    `pip install --user`): bootstrap `uv`, which brings its own venv builder and
    can supply its own Python, so no system venv package is needed:
    `curl -LsSf https://astral.sh/uv/install.sh | sh`
    The installer prints the bin dir (usually `$HOME/.local/bin`); add it to PATH
    or call `uv` by full path in the same session. Then, from the project root,
    `uv venv && uv pip install -e .` — this replaces steps 3-5. Continue at step 6.
    (If system Python is older than 3.10 or missing, add `uv python install 3.12`
    before `uv venv`.)
- macOS: install Python via python.org or `brew install python`; `python3 -m venv` works out of the box.
- Windows: install Python from python.org with "Add python.exe to PATH" checked; `py -m venv` bundles pip.
- Any OS with `uv` already installed: `uv venv && uv pip install -e .` also works.

## 4. Upgrade pip and Build Tools

macOS / Linux / WSL:

```bash
.venv/bin/python -m pip install --upgrade pip setuptools wheel
```

Windows PowerShell:

```powershell
.venv\Scripts\python -m pip install --upgrade pip setuptools wheel
```

## 5. Install Package

Install the local source in editable mode.

```bash
.venv/bin/python -m pip install -e .
```

If the user asks for tests or development setup:

```bash
.venv/bin/python -m pip install -e ".[test]"
```

## 6. Create `.env`

If `.env` does not exist, copy it from `.env.example`.

```bash
test -f .env || cp .env.example .env
```

If `.env` already exists, do not overwrite it.

## 7. Configure LLM Runtime

This project is positioned around premium report generation through Claude Code / Codex CLI, not API-only metered execution.

**Auto-detect first — do not ask the user to choose manually.** Detect which CLI
runtime is already installed and configure `.env` accordingly. This whole step
should be automatic from the user's point of view.

### 7.1 Detect the installed CLI

```bash
command -v codex && codex --version
command -v claude && claude --version
```

Decision rule:

- If **only `codex`** is installed → provider is `codex-cli`.
- If **only `claude`** is installed → provider is `claude-cli`.
- If **both** are installed → default to `codex-cli` (the documented public
  default). Only pick `claude-cli` if the user explicitly asked for Claude.
- If **neither** is installed → go to 7.3 and help the user install one.

Note: the runtime also auto-detects at import time. If you leave
`TRADINGAGENTS_LLM_PROVIDER` blank/unset in `.env`, `default_config.py` runs the
same detection (`codex` preferred, then `claude`). Writing the block below is
still recommended so the choice is explicit and reproducible.

### 7.2 Write the matching block into `.env`

For Codex CLI (default):

```bash
TRADINGAGENTS_LLM_PROVIDER=codex-cli
TRADINGAGENTS_QUICK_MODEL=gpt-5.5
TRADINGAGENTS_DEEP_MODEL=gpt-5.5
TRADINGAGENTS_CLI_TIMEOUT=1800
```

For Claude Code CLI:

```bash
TRADINGAGENTS_LLM_PROVIDER=claude-cli
TRADINGAGENTS_QUICK_MODEL=sonnet
TRADINGAGENTS_DEEP_MODEL=opus
TRADINGAGENTS_CLI_TIMEOUT=1800
# Reasoning effort — claude-cli only (codex-cli ignores it): low|medium|high|xhigh|max
# This project is premium-report-first, so max is the recommended default.
# Lower it (e.g. medium) if the user wants faster, cheaper runs.
TRADINGAGENTS_CLI_EFFORT=max
```

Replace the existing `TRADINGAGENTS_LLM_PROVIDER` / `TRADINGAGENTS_QUICK_MODEL` /
`TRADINGAGENTS_DEEP_MODEL` lines in `.env` in place (do not append duplicates).
`TRADINGAGENTS_CLI_EFFORT` only applies to `claude-cli`; when configuring
`codex-cli` you can leave it unset or commented. Never echo secrets while editing.

### 7.3 If neither CLI is installed

Tell the user this project needs one CLI runtime, and offer to install it. Do not
silently switch to an API-provider mode.

Codex CLI:

```bash
npm install -g @openai/codex
codex login
```

Claude Code CLI:

```bash
npm install -g @anthropic-ai/claude-code
claude   # then complete the interactive login/subscription auth
```

Both require Node.js. After the user installs and authenticates one runtime,
re-run the detection in 7.1 and write the matching block from 7.2. Login is
interactive and account-bound — the user must complete it themselves; never ask
for or handle their credentials.

## 9. Verify Installation

### 9.1 Confirm the package is actually installed (authoritative)

Run this first. It works from any directory and cannot be faked by the source
tree:

```bash
.venv/bin/python -m pip show tradingagents
```

- Exit 0 with `Name` / `Version` / `Editable project location` printed → the
  editable install from step 5 succeeded.
- Exit 1 / `Package(s) not found` → `pip install -e .` did **not** complete. Do
  not treat setup as done. Re-run step 5 and, if `python -m pip` reports "No
  module named pip", recreate the venv per steps 2-4 (on Debian/Ubuntu install
  `python3-venv` first).
- Note (uv fallback): a `uv venv` environment does **not** bundle `pip`, so
  `.venv/bin/python -m pip show ...` prints "No module named pip" even when the
  install succeeded. In that case use `uv pip show tradingagents` as the
  authoritative check (same `Name` / `Version` / `Editable project location`
  output), or fall back to `.venv/bin/tradingagents --help`.

> Why this comes first: a bare `import tradingagents` run from the project root
> succeeds even when the install failed, because the `tradingagents/` source
> directory in the working dir shadows the (missing) installed package. Always
> gate on `pip show` above, not on the import check alone.

### 9.2 Import check (provider sanity)

```bash
.venv/bin/python - <<'PY'
import tradingagents
from tradingagents.default_config import DEFAULT_CONFIG
print("TradingAgents Korea import OK")
print("LLM provider:", DEFAULT_CONFIG.get("llm_provider"))
PY
```

CLI module check:

```bash
.venv/bin/python -m cli.main --help
```

Console script check:

```bash
.venv/bin/tradingagents --help
```

Preflight onboarding check:

```bash
.venv/bin/tradingagents doctor
```

Use this to show missing CLI runtimes and unfilled recommended API key groups
without printing any secret values.

Some interactive CLI commands may behave differently by terminal environment. If
`pip show` (9.1) confirms the install and the checks above run, setup can be
considered complete even if a help command is interactive or noisy.

## 10. Run Examples

Do NOT run these as part of install verification — step 9 already confirms the
install. These are real analysis runs: `main.py` needs live KIS/Naver/DART/ECOS
keys and an authenticated CLI runtime, and a full run can take 15+ minutes. The
bare interactive CLI (`cli.main` / `tradingagents`) opens a prompt and will hang
a non-interactive agent. Only run these when the user actually asks for a report,
after the keys from step 8 are filled in.

Basic run:

```bash
.venv/bin/python main.py 005930
```

With explicit date:

```bash
.venv/bin/python main.py 005930 YYYY-MM-DD
```

Interactive CLI:

```bash
.venv/bin/python -m cli.main
```

or:

```bash
.venv/bin/tradingagents
```

## 11. Final Response to User

After setup, give the user a short operational summary. Do not paste this whole file.

Include:

- Whether setup completed
- Python version used
- LLM provider configured (`codex-cli` or `claude-cli`)
- Which data API keys still need to be filled in `.env`
- One or two run commands

Example:

```text
Setup is complete.
I created `.venv`, installed the package, and verified imports.
The LLM runtime is configured as `codex-cli`.
Fill KIS/Naver/DART/ECOS keys in `.env`, then run:
```

## 12. Safety Notes

- Never commit `.env`.
- Never print real API keys or tokens.
- Never expose KIS account identifiers, token caches, Notion private URLs, or Telegram tokens.
- This project is not investment advice and not an automated trading system.
- Premium reports can take a long time. Do not set short timeouts; 30+ minute runs may be normal.
- Keep the project aligned with local CLI-based premium report generation.
